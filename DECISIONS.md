# Decision Log

An evolving record of UX design decisions, in chronological order.

| Date | Decision | Rationale |
|------|----------|-----------|
| 2026-06-26 | PageContents active links use a selected background instead of increased font weight | Changing font weight caused text reflow as the active section changed; a background communicates selection while keeping link dimensions stable and avoiding a distracting left accent line |
| 2026-06-25 | Stark reserves black/white selected states for navigation only | Full black selected backgrounds across pickers, chips, and form controls felt too heavy; navigation can use the stronger active state while ordinary selected controls keep subtler fills and readable input borders |
| 2026-06-23 | Terminal theme added as a dark, mono-forward command-line surface with green/amber accents and sharp geometry | Provides a radical developer/admin mood for system-heavy tools while keeping input borders, focus states, and primary actions high contrast |
| 2026-06-23 | Ledger theme added as a restrained finance/backoffice surface with off-white canvas, green/navy actions, and visible ruled-line borders | Gives the library a serious operational theme suited to dense tables and admin workflows without relying on generic neutral gray |
| 2026-06-23 | Blueprint theme added with technical blue page grids, precise radii, translucent chrome, and blur-backed top navigation | The drafting-paper direction makes planning/specification pages feel distinctive while using the page background and chrome tokens introduced for richer themes |
| 2026-06-23 | Aurora theme added with soft teal/coral gradient page backgrounds, glassy surfaces, rounded controls, and blurred transparent chrome | Adds a more futuristic theme option that uses richer page canvas treatment while preserving readable semantic text and input contrast |
| 2026-03-31 | SidePanel `actions` prop accepts `React.ReactNode` (arbitrary content) | Keeps the API flexible — callers bring their own buttons, menus, or any control without the component needing to constrain the shape |
| 2026-03-31 | Actions in the SidePanel header are separated from the close button by `space-s` (8px) | Creates clear visual grouping while keeping the header compact; close button always anchors to the far right |
| 2026-03-31 | SidePanel header height is driven by the `--admin-panel-header-height` semantic token (48px) | Aligns SidePanel header with TopNav sm height for consistency; token makes the relationship explicit and easy to change globally |
| 2026-03-31 | RichTextEditor in popover mode caps at 300px max-height with overflow scroll | Prevents the popover from growing unbounded with long content; 300px provides enough reading area without dominating the viewport |
| 2026-04-02 | SegmentedControl pinned options use `pin: 'left' | 'right'` per-option rather than separate arrays at the control level | Keeps pin intent co-located with the option definition; avoids the control needing to cross-reference two separate lists |
| 2026-04-02 | Pinned sections show a subtle drop shadow when scrollable content is hidden behind them | Shadow is the standard affordance for frozen columns/sections; communicates that content exists beyond the visible edge without adding permanent chrome |
| 2026-04-02 | Removing `overflow: hidden` from SegmentedControl outer wrapper to fix selected segment shadow clipping | `overflow: hidden` was cutting off the box-shadow on selected items at the container edges; border-radius clips the background without needing it |
| 2026-04-02 | Line tool stays as its own toolbar button, separate from the shapes popover | Line has no fill/outline mode so it behaves differently from the shape tools; grouping it would be misleading |
| 2026-04-02 | Shape tools (rect, circle, triangle, star) consolidated into a single toolbar button with a vertically-stacked popover | Four separate buttons consumed too much toolbar space; the single button with popover matches the brush size pattern and keeps the toolbar scannable |
| 2026-04-02 | Shape toolbar button shows the icon of the currently active or last-used shape | The button needs to reflect state (which shape and fill mode) so the user can see their active tool at a glance without opening the popover |
| 2026-04-02 | Pressing an already-active shape in the popover toggles fill/outline and closes the popover | Preserves the existing toggle behaviour; closing on any action avoids leaving the popover open after making a selection |
| 2026-04-02 | Canvas mousedown closes any open tool popover (brush or shapes) | Drawing is the primary action; open popovers during a draw stroke would be visually confusing and occlude the canvas |
| 2026-04-02 | PixelArtEditor undo stack capped at 50 entries | Bounds memory usage; 50 steps is generous for a pixel art tool without being excessive |
| 2026-04-02 | Undo/redo toolbar buttons placed left of Download and Trash | Groups history actions (undo/redo/clear) together; clear is the most destructive so anchoring it to the far right provides a natural visual buffer |
| 2026-04-02 | GradientPicker closes the color picker popover when the gradient bar or a stop handle is interacted with | Clicking the bar or dragging a stop is a distinct action from editing a color; leaving the picker open would create visual clutter and interaction confusion |
| 2026-04-02 | SidePanel overlay mode gets a visible scrim (`--admin-overlay` background on the backdrop) | The invisible full-screen backdrop was blocking all mouse events in the host app; a visible scrim also correctly communicates modality to the user |
| 2026-04-02 | SidePanel push mode renders inline with no backdrop, shadow, or border radius | Push mode is for persistent panels that coexist with content rather than overlaying it; shadow and radius are overlay affordances that don't apply when the panel is part of the layout flow |
| 2026-04-02 | SidePanel push mode requires the consumer to provide a flex container | The panel animates its width from 0 to target, pushing sibling content; the library can't control the host layout so the consumer must opt in with a flex parent |
| 2026-04-02 | SidePanel header title uses `type-heading-xs` and the close button uses `size="sm"` | The previous `type-heading-s` title felt too large for a panel header; `xs` is more proportional and consistent with other compact header patterns in the library |
| 2026-04-02 | DatePicker single mode always closes after selection with no `autoClose` prop needed | Closing after selection is the standard UX for a single-date picker; the `autoClose` opt-in was an unnecessary indirection that diverged from user expectations |
| 2026-04-02 | DatePicker range mode tests use `vi.useFakeTimers({ toFake: ['Date'] })` to fix "today" without breaking userEvent | Mocking only the Date constructor leaves real timers intact so userEvent's internal async logic still works; full fake timers caused test timeouts |
| 2026-04-02 | Pen tool commits the entire polyline as a single undo step | Each segment is part of one intentional gesture; per-segment undo would require many steps to undo a simple shape and would not match user expectations |
| 2026-04-02 | Pen tool finishes on Enter, double-click, or clicking within 1 cell of the first anchor (closes shape) | Three complementary gestures cover keyboard-first, mouse-first, and shape-closing workflows; Escape cancels without committing |
| 2026-04-02 | Pen tool uses `PenTool` from lucide-react for its toolbar icon | Matches the existing pattern of using lucide icons for all toolbar buttons; `PenTool` specifically represents a vector pen/path tool which matches the interaction model |
| 2026-04-03 | PixelArtEditor toolbar rows use uniform `--admin-space-xs` padding on all sides | The previous horizontal `--admin-space-s` padding was visually unequal to the vertical `--admin-space-xs`; uniform padding looks balanced and respects the token system |
| 2026-04-03 | Custom colors picked via the color wheel are saved to a per-session swatch list, prepended at the start | Lets users quickly reuse a recently picked color without reopening the wheel; placing new colors at the start means the most recently used is always reachable without scrolling |
| 2026-04-03 | The custom swatch button's active ring hides once the color has been saved to the custom list | Once a color appears in the scroll list it has a swatch of its own; keeping the custom button highlighted alongside it would create a redundant, confusing active state |
| 2026-04-03 | Collapsed `--admin-background-*` tokens into `--admin-surface-*` with deprecated aliases | Two-tier naming (surface + background) for the same concept was redundant and inconsistent; single tier with aliases preserves backwards compatibility for external consumers |
| 2026-04-03 | Renamed `--admin-interactive-subtle` to `--admin-interactive-hover`; kept alias | The old name described appearance rather than intent; hover/active/selected/focus names make the state machine explicit |
| 2026-04-03 | Added `--admin-interactive-selected` distinct from `--admin-interactive-active` | Active (pressed) is a transient state; selected (current item) is persistent — conflating them with one token prevented visual differentiation between the two |
| 2026-04-03 | Fixed `--admin-interactive-focus` to reference `--admin-border-highlight` (brand colour) | The token was set to a near-invisible grey, making focus rings effectively invisible; brand-coloured focus rings meet accessibility expectations and match input focus borders |
| 2026-04-03 | SegmentedControl hover uses `--admin-surface-subtle` instead of `--admin-interactive-hover` | The track background and the hover state resolved to the same token value, making hover invisible; one step up the surface scale creates a visible distinction |
| 2026-04-03 | Added `--admin-button-radius` and `--admin-interactive-radius` component-role tokens | Without role tokens a shape theme requires touching every file; these two tokens cover all interactive item and button shapes and make shape theming a single-point override |
| 2026-04-03 | Added `--admin-opacity-disabled: 0.5` and standardised all disabled states | Disabled opacity varied across components (0.3, 0.35, 0.4, 0.5); a single token ensures visual consistency and makes the value themeable |
| 2026-04-03 | Added `--admin-code-*` tokens for CodeBlock; component is always dark regardless of theme | CodeBlock uses a GitHub-style dark syntax palette that should not invert in light mode; tokens make the palette overrideable without baking in raw hex values |
| 2026-04-03 | Added `--admin-button-primary-*` and `--admin-button-destructive-*` tokens; removed `filter: brightness()` hover | Filter-based hover is not inspectable or overrideable via tokens; explicit hover-bg tokens make button colours fully themeable |
| 2026-04-03 | Added `--admin-button-text-transform: none` token | Allows themes to opt into uppercase buttons without touching component CSS; default of `none` preserves existing behaviour |
| 2026-04-03 | Added `input-wrapper` mixin for compound inputs (CompactInput, ColorPicker swatchFrame) | These components use `:focus-within` on a container div, not `:focus` on the input — a distinct enough pattern from `input-base` to warrant its own mixin |
| 2026-04-03 | Themes use `data-admin-theme` with `~=` word-match selectors to support composition | Word-match allows `data-admin-theme="ocean rounded"` to apply two themes simultaneously; dark mode stacks independently via the existing `data-theme="dark"` attribute |
| 2026-04-03 | Slate theme bakes in `sharp` radius values rather than requiring composition | Slate's aesthetic (technical, structured) calls for flat corners; the combination is intentional and baking it in avoids consumers needing to remember to compose both |
| 2026-04-03 | RichTextEditor focus-within drops the outline, keeps only border-colour change | After fixing `--admin-interactive-focus` to brand colour, the wrapper showed a double blue ring (border + outline); the border colour change alone is sufficient for a container element |
| 2026-04-03 | mixins.css and themes.css added to the library bundle via src/styles/index.css | Both files existed but were not imported, making them invisible to consumers; adding them ensures theming and mixin utilities are available after a single stylesheet import |
| 2026-04-03 | Toast placed in overlays/ rather than primitives/ | Toast is floating, fixed-position UI — the same category as Modal and SidePanel; primitives are non-positioned leaf components |
| 2026-04-03 | Toast exposed as Toast + ToastStack pair with no context/provider | A provider adds global state complexity; a stateless stack component that accepts an array of toasts lets the caller own state with standard useState, which is simpler and more flexible |
| 2026-04-03 | DataGrid supports both controlled and uncontrolled sort/selection | Consumers who manage their own data need controlled mode (server-side sort); those with local data benefit from uncontrolled defaults; dual-mode keeps the API useful in both cases |
| 2026-04-03 | Divider sizes are sm=1px, md=2px, lg=4px (thickness, not spacing) | "3 sizes" for a divider means visual weight, not height/margin; thickness progression is the meaningful variation |
| 2026-04-03 | No new design tokens added to design-system.css for any of the 7 new components | All required colours, spacing, radius, and elevation were already covered by existing semantic tokens; adding tokens only where the existing vocabulary genuinely cannot express the concept |
| 2026-04-03 | Right-click on the PixelArtEditor canvas is ignored (`e.button !== 0` guard in `handleMouseDown`) | Right-click was triggering drawing before the context menu opened, causing phantom strokes that couldn't be undone; ignoring non-primary button events prevents this entirely |
| 2026-04-03 | Undo and Redo added to the PixelArtEditor context menu with keyboard shortcut hints | Undo/redo are core editing actions; exposing them in the context menu makes them discoverable for users who haven't learned the keyboard shortcuts, and shortcut hints reinforce the shortcuts |
| 2026-04-03 | DocPage `centered` prop defaults to `true`, controlling whether content is max-width constrained and centred | Most doc pages should be centred; opting out via `centered={false}` is the uncommon case, so the default preserves existing behaviour without requiring callers to pass anything |
| 2026-04-03 | DocPage accepts a `maxWidth` prop (number or string) as a consumer-controlled override | Different doc pages need different widths; baking a single value into the component would be too rigid; an inline style override keeps it flexible without adding new tokens |
| 2026-04-03 | Stack and Columns added as explicit layout primitives rather than CSS utility classes | Named components are composable, discoverable, and typesafe; utility classes require consumers to know the right class names and don't surface in component catalogs |
| 2026-04-03 | SectionHeading accepts size aliases (s, sm, small / m, md, medium / l, lg, large) via `resolveSize` | Consistent with Button, Avatar, and other components that already accept the same alias set; reduces friction when consumers switch between components |
| 2026-04-03 | Shared `SizeSmMd` and `SizeSmMdLg` union types extracted into `resolveSize.ts` | The same size alias set was duplicated across Button, Avatar, Badge, Select, ToolbarButton; a single canonical type prevents drift and makes the pattern explicit |
| 2026-04-03 | Command component is built by composing existing library patterns (Modal animation, GlobalSearch keyboard nav) | Re-implementing scroll-into-view, ↑↓ navigation, and overlay animation from scratch would diverge from established behaviour; composing existing patterns keeps the UX consistent |
| 2026-04-03 | CommandDialog z-index set to 10003 (backdrop) / 10004 (panel), above ContextMenu (10002) | Command palette must appear above all other floating UI; layering above ContextMenu ensures it is never obscured when invoked from a context menu item |
| 2026-04-03 | Kbd component uses `extra-subtle` background and no border | A border made Kbd feel too heavy relative to surrounding text; extra-subtle background provides enough contrast to distinguish the key label without visual noise |
| 2026-04-03 | Added `--admin-border-info/success/warning/error` semantic tokens for status borders | Components like Banner needed a border colour that communicates status; reusing surface tokens for borders broke the semantic contract (surface ≠ border) and produced low-contrast borders |
| 2026-04-03 | Banner updated to use `--admin-border-*` status tokens instead of surface tokens for its border | Banner's coloured border is a status signal, not a fill; the dedicated border tokens ensure correct contrast in both light and dark mode and make the intent explicit |
| 2026-04-06 | `makeAvatar` accepts an `eyeSpacing` prop (default 5) controlling total horizontal distance between eye centers | Enables diversity in avatar faces; default matches the previous hardcoded value so existing avatars are unchanged |
| 2026-04-06 | Glasses frames in `makeAvatar` use `eyeHalf * 1.6` offset rather than matching eye positions exactly | Glasses naturally sit wider than just the pupils; the 1.6× ratio reproduces the original visual spacing while still scaling with `eyeSpacing` |
| 2026-04-06 | Chip with avatar gets zero vertical and left padding; left border-radius matches the avatar's corner curve | The avatar is a 20×28px shape with `border-radius: 9999px` — its effective corner is `10px`; matching it eliminates the gap and misaligned curve between avatar and chip border |
| 2026-04-06 | Chip left border-radius uses explicit `border-top-left-radius: 10px` / `border-bottom-left-radius: 10px` rather than a CSS variable | The radius must match the avatar's physical pixel dimensions (half of 20px width), not a theme token; hardcoding avoids it being accidentally overridden by a shape theme |
| 2026-04-06 | `xs` Avatar size added (20×28px) to match `--admin-input-height-sm` (28px) | Chip with avatar needs the avatar height to fill the chip exactly; a dedicated `xs` size tied to the input height token keeps the Chip layout predictable |
| 2026-04-06 | Chip component uses `size="xs"` avatar when rendering its avatar slot | Chip height is `--admin-input-height-sm`; using the matching `xs` avatar size ensures the avatar fills the chip without clipping or gaps |
| 2026-04-06 | Decisions catalog page renders table rows in reverse chronological order (newest first) | The most recently made decisions are the most relevant; reversing at render time keeps the source file append-only without requiring manual reordering |
| 2026-04-09 | `swept` hairstyle added to `makeAvatar` — side-swept wave over the forehead | Expands avatar personality range; swept/slicked hair is a visually distinct style not covered by short, spiky, or fringe |
| 2026-04-09 | Sample avatars section in the Avatar catalog displays at `lg` size | Larger avatars make the style variation across the sample set clearly visible; smaller sizes obscure the detail differences |
| 2026-04-09 | `xl` Avatar size added at 72×100px, maintaining the ~0.71 width:height ratio of existing sizes | Provides a size step for profile headers and other large-format contexts; consistent ratio keeps the avatar silhouette proportional at all sizes |
| 2026-04-11 | Co-located sub-components each get their own test file rather than being covered only through parent tests | Testing via the parent hides which sub-component surface broke; isolated tests pinpoint failures and make each component's contract explicit |
| 2026-04-11 | Canvas-heavy components (ColorWheel, AnimationPreview) are tested at the jsdom level: render, callbacks, and accessible controls only — no canvas drawing assertions | jsdom's canvas has no 2D context; asserting drawing output would always pass vacuously and test nothing real. Utility functions (hsvToHex, hexToHsv) are unit-tested directly instead |
| 2026-04-11 | BezierEditor pointer-drag tests mock `getBoundingClientRect` to a known 200×200 rect | jsdom returns zeros for all rects; without a mock, all drag coordinates resolve to the same point and onChange never fires with meaningful values |
| 2026-04-12 | ESLint 9 flat config (`eslint.config.js`) added with TypeScript-ESLint, react-hooks, and Prettier compat | No linter existed; consistency was enforced by convention alone; ESLint 9 flat config is the current standard and required since the project uses `"type": "module"` |

| 2026-04-12 | `react-hooks/exhaustive-deps` violations kept as warnings rather than errors | The violations in SideNav, ContextMenu, Toast, and Slider are intentional — including the omitted deps would break the intended effect timing; errors would block CI on deliberate design choices |
| 2026-04-12 | Vitest coverage thresholds set to 70% for lines and functions | Provides an enforceable floor that current coverage can meet; `@vitest/coverage-v8` chosen for zero-config compatibility with Vite |

| 2026-04-12 | Prettier config matches existing code style: singleQuote, semi, trailingComma=all, printWidth=100 | Matching observed code style prevents formatter churn on first run and avoids reformatting unrelated lines in every future PR |
| 2026-04-12 | Silent catch blocks log via `console.error` with a `[ComponentName]` prefix | Prefixed component name makes DevTools filtering trivial and immediately correlates an error to its source without needing a stack trace |
| 2026-04-14 | Marquee selection persists across tool switches as a live mask | Previously the selection disappeared when switching tools; persisting it lets users draw within a bounded region without re-selecting after every tool change |
| 2026-04-14 | Fill tool with active selection: click inside fills the entire selection rectangle | Flood-filling from the click point inside a selection was unintuitive; block-filling the whole rectangle matches the "selection as stencil" mental model |
| 2026-04-14 | Fill tool with active selection: click outside flood-fills the exterior only | Selection acts as a complete two-sided mask; clicking outside constrains the flood fill to the unselected region, making the selection a true barrier |
| 2026-04-14 | All drawing tools constrained to whichever side of the selection the stroke starts on | Starting inside keeps changes inside; starting outside keeps changes outside; the start position at mousedown determines the constraint for the entire stroke |
| 2026-04-14 | Selection dismissed via Cmd+D (matching Photoshop's Deselect shortcut) | Photoshop's shortcut is widely known; using it avoids users needing to switch back to the marquee tool just to clear the selection |
| 2026-04-14 | Dedicated "Fill selection" toolbar button removed in favour of fill-tool-native behaviour | With the fill tool handling selection-aware fills natively, the separate button was redundant and added clutter to the toolbar |
| 2026-04-14 | Dark mode `surface-subtle` and `surface-extra-subtle` use solid tokens (`black-85`, `black-95`) instead of `white-alpha-10` | Alpha tokens compound when layered — a hover state inside a card that already uses an alpha surface produces a visibly brighter result; solid tokens eliminate this regardless of stacking order |
| 2026-04-14 | Added `black-85` (#1e1e1e) and `black-95` (#141414) to the primitive colour scale | No solid step existed between `black-80` (#282828) and `black-90` (#101010); the two new steps provide the correct visual weight for subtle dark surfaces without requiring alpha |
| 2026-04-14 | `PageContents` is data-driven (consumer passes `PageContentsItem[]`) rather than scanning the DOM for headings | DOM scanning couples the component to page structure; the consumer already knows which sections exist and can express them explicitly without hidden coupling |
| 2026-04-14 | `PageContents` has no placement opinion — consumer is responsible for positioning (sticky, sidebar, inline) | Placement varies by page layout; the component should not impose a position scheme that consumers will override |
| 2026-04-14 | `PageContents` scroll-spy uses a fixed `rootMargin: '-10% 0px -80% 0px'`; no threshold prop exposed | The threshold is an implementation detail that consumers have no meaningful reason to tune; exposing it adds API surface for an edge case better handled by a custom hook |
| 2026-04-14 | Nesting uses a recursive tree (`children?: PageContentsItem[]`) rather than a flat list with a `level` field | The hierarchy is explicit in the data structure, preventing orphaned child items; flat+level requires consumers to maintain ordering invariants that the tree enforces automatically |
| 2026-04-14 | Active state propagates to all ancestors of the active item | When a child section is active the parent link should also appear active; this keeps the user oriented within the hierarchy and avoids the parent looking inactive |
| 2026-04-14 | `PageContents` renders a maximum of two levels; no deeper recursion | Admin pages rarely need deeper hierarchy and extra nesting complicates the visual weight; two levels (parent + children) cover all realistic use cases |
| 2026-04-14 | `label` prop is optional; omitting it renders no heading above the links | Whether to show "On this page" depends on the page context, not the component; consumers opt in to the heading rather than suppressing it |
| 2026-04-15 | ImagePicker trigger shows the selected image name as text alongside the thumbnail | The thumbnail alone gives no accessible or scannable label; showing the name means the selection is readable at a glance without opening the popover |
| 2026-04-15 | ImagePicker popover uses a vertical list rather than a grid | A list accommodates variable-length names without truncation anxiety and makes the filter result set easier to scan; a grid of thumbnails prioritises visual pattern-matching which is less useful when images have meaningful names |
| 2026-04-15 | ImagePicker popover has an `InlineSearch` filter autofocused at the top | Pickers with many images require quick narrowing; autofocusing the filter means the user can type immediately after opening without an extra click |
| 2026-04-15 | ImagePicker popover max-height is 340px with vertical scroll | Prevents the popover from dominating the viewport; 340px shows roughly 10 items before scrolling, which is sufficient without feeling truncated |
| 2026-04-15 | ImagePicker trigger fills available horizontal space and uses `--admin-input-height-md` for height | Hardcoded pixel values (32px width cap, 32px height) prevented the trigger from adapting to its layout context; token-based height and `width: 100%` align it with other input controls |
| 2026-04-15 | `--admin-text-placeholder` added as a dedicated semantic token distinct from `--admin-text-subtle` | Placeholder text is a distinct semantic role — separating it from `--admin-text-subtle` allows independent tuning per theme and makes intent explicit in every usage site; all `::placeholder` pseudo-elements and placeholder-style spans now reference this token |
| 2026-04-15 | TopNav dropdown tabs are hover-only triggers with no active/selected state | Dropdown tabs are navigation launchers, not section indicators; showing them as active would be misleading since the user navigates via an item click rather than the tab itself |
